## 一、结论速览

**能做，而且这台设备有打砖块罕见的先天优势。**

这台 Kindle Basic（第 7 代）是 **16 级灰度**面板（不是 1bpp），比《方块战争》那类 1bpp 界面多出整整一个维度的表现力——可以用**真实灰阶**编码砖块状态，用**形状**编码语义，而不是靠闪烁和动画。

真正的敌人不是玩法，而是**墨水屏物理**：有效刷新率只有 5–15 fps，且局部刷新会留下灰影。经典打砖块的核心体验是"球在飞"，这与墨水屏天然冲突。

本方案的三条对策：

| # | 对策 | 一句话 |
|---|------|--------|
| 1 | **格点步进物理** | 球不再连续飞行，而是以固定 tick 沿速度方向步进；子步细分杜绝穿模，手感保持真实的"击球点决定角度" |
| 2 | **静态预测代替连续动画** | 用**落点标记**和**发射射线**替代实时轨迹动画——静态元素刷新干净、不留残影，还让玩家从"纯反应"升级为"预判瞄准" |
| 3 | **分区刷新 + 残影预算** | 每帧只刷新"运动脏区"（球/挡板/标记），砖阵区低频维护刷新；把残影当成**有预算的资源**来管，而不是任其积累 |

交付形态：与《方块战争》同构的 **KOReader 插件** `plugins/breakout.koplugin/`，全屏 600×800 触控。

## 三、玩法调研：打砖块到底是怎么做的

### 3.1 经典机制的共识部分（自 Atari 1976 Breakout → Taito 1986 Arkanoid → 今日各类复刻）

所有资料高度一致的核心循环：

1. **挡板回弹**：球撞到挡板的**哪个位置**决定出射角——正中≈垂直向上，边缘≈大角度斜飞。这是整个品类的**技巧天花板**，不是装饰。
2. **砖块层级**：普通砖一击即碎；多血砖需连续命中；不可破砖永远打不掉，只作**反弹障碍**改变球路。
3. **关卡递进**：清空全部可破砖 → 下一关 → 砖阵布局变化 + 球速提升。
4. **生命制**：球掉到挡板下方扣一条命；命数归零结束。
5. **计分**：普通砖 10 分，多血砖 20/30 分，不可破砖 0 分；额外生命、多球等道具再加分。

### 3.2 Arkanoid 引入的道具（Power-ups）

打碎砖块后**掉落胶囊**，用挡板接住：

| 道具 | 效果 | 分类 |
|---|---|---|
| Catch（黏球） | 球吸附在挡板上，可择机发射 | 精度型，最强 |
| Enlarge（加长挡板） | 挡板变宽 | 防守型 |
| Slow（减速） | 球速下降（可叠加） | 节奏型 |
| Disruption（分裂） | 一球变三球 | 爆发型 |
| Laser（激光） | 挡板可发射激光直接打砖 | 进攻型 |
| 反向道具 | 加速 / 挡板变短 / 即死 | 惩罚型 |

### 3.3 进阶玩家技巧（决定手感设计）

- **落点预判**：站在球**将要落点**下方，而不是球现在在哪。
- **边缘击球定向**：用挡板边缘制造大角度，专打角落与侧墙后的砖。
- **天花板陷阱**：把球送到砖阵上方，球在顶墙与顶行之间反复弹跳，**不用手也能自动清一片**——这是高手的核心效率手段。
- **侧墙走位**：贴墙竖列反复弹跳，一次清一整列。

### 3.4 调研结论 → 本项目的取舍

| 调研结论 | 本项目决策 | 理由 |
|---|---|---|
| 击球点决定角度是核心技巧 | **完整保留并强化**：挡板 96px 宽，击球点决定 ±51° 出射角，并保证横向分量不小于 12%（防垂直死循环） | 这是品类灵魂，删了就不是打砖块 |
| 砖块层级带来策略深度 | **保留 4 型**：普通 / 2 血 / 3 血 / 不可破 | 墨水屏上靠**明度+形状**编码，零动画成本 |
| 关卡递进 | **4 个手工关 + 第 5 关起程序化生成**，球速逐关递增 | 手工程序质量高，程序化保证长线可玩 |
| 道具系统（6 种） | **做：7 种掉落道具**（v1.1 起） | 原判断"掉落物 = 第二个持续运动物体"成立，但可用"**专用道具砖 + 徽章慢速直落（100px/s）**"折中：徽章是纯几何静态图标，场上最多 1~4 个额外运动物体，残影可控 |
| 技巧依赖"预判落点" | **落点标记**（飞行中实时预测落点并打十字） | 墨水屏无法承载连续轨迹动画，但**可以**承载一个静态小标记；把纯反应游戏升级为可瞄准游戏，正合 e-ink 之长 |
| 技巧依赖"天花板陷阱" | **可用**：预测与反弹均为真实物理，玩家能主动制造该局面 | 无需额外机制 |
| 多球（Disruption） | **做：上限 4 球**（v1.1 起） | 关键设计：**只有全部球都掉出底线才扣命**（对慢节奏玩家友好）；多球时只预测**最迫近那一颗**的落点，避免标记过多导致残影过重 |

## 四、墨水屏三条硬约束与设计对策

### 约束一：有效刷新率只有 5–15 fps

任何"球在连续飞"的实现都会变成"球在跳格"。

**对策 A：格点步进物理（Grid-stepped physics）**

- 游戏循环固定 `TICK = 100ms`，球每 tick 沿当前速度方向**步进固定距离**（15–26px）。
- 角度完全自由（连续物理），只是**渲染位置被量化**——手感是真实打砖块，画面是诚实的墨水屏跳格。
- 单 tick 位移拆成 ≤5px 的**子步**（`SUBSTEP`），逐子步做碰撞检测，彻底杜绝穿模。砖块宽 52px，5px 子步有 10 倍安全余量。

**对策 B：把"不可读的运动"换成"可读的信息"**

| 想表达 | 连续动画方案 | 本项目方案 |
|---|---|---|
| 球会往哪飞 | 逐帧绘制轨迹 | **落点十字标记**（静态、小、刷新代价低） |
| 发球方向 | 箭头动画 | **短虚线射线**（约 70px，静止时几乎不产生 diff） |
| 球有多快 | 速度条闪烁 | 底栏**常驻数字**（速度值） |

### 约束二：局部刷新留残影（幽灵图像）

Kindle 16 级灰度面板做局部刷新时，**黑→白**的像素会残留一层浅灰，直到该区域被再次刷新。

**核心对策：分区刷新 + 残影预算**

KOReader 的 `setDirty(widget, "ui", region)` 会**强制推送指定区域**（与像素是否变化无关），这给了我们精确治理残影的能力：

| 区域 | 刷新频率 | 目的 |
|---|---|---|
| **运动脏区**（球/挡板/标记的并集 + 12px 余量） | **每 tick (10Hz)** | 保证运动物体清晰；球走过的地方被反复刷新，旧残影在 2–3 帧内衰减 |
| **砖阵区**（547×159，约占屏 19%） | **每 5 tick (500ms)** + 击碎砖块时立即触发 | 清理砖块被击碎后残留的"灰色坑洞"；只刷 19% 屏幕，代价可控 |
| **全屏全刷**（`"full"`，黑闪约 1s） | **仅在关卡切换 / 结束时** | 兜底彻底清场；游戏中绝不做，避免频繁黑闪打断节奏 |

**残影预算原则**：任何时刻，屏上残留的灰影不超过"刚击碎的那一块砖"的范围。游戏全程黑闪次数 = 关卡数，而不是每 2 秒一次。

**同时接受一个视觉事实**：球每 100ms 跳 15px，屏上会留下一串淡灰"弹道点"。这是墨水屏的物理必然，**但不掩饰它，而是把它变成设计**：弹道点本身就是玩家读轨迹的信息，静态元素刷新干净、不累积脏影。

### 约束三：1bpp 时代的经验不能直接搬

《方块战争》跑在墨水屏上，但本项目所在设备是 **16 级灰度**：

- 砖块血量 **用真实灰阶编码**，不用动画/闪烁。
- 不可破砖用**浅灰底 + 黑描边 + 黑菱形点阵**，与可破砖在明度和纹理上双重区分——玩家扫一眼就知道"这块打不掉"。
- 多血砖用**白色 pip 标记**（2 血 1 个、3 血 2 个），比"换个颜色"在灰度屏上更可靠。

### 5.2 砖块类型（灰阶 + 形状双编码）

| 类型 | 外观 | 血量 | 分值 |
|---|---|---|---|
| 普通 | **深灰底(0x33)** | 1 | 10 |
| 强化 | 纯黑 + 中心 1 个白 pip | 2 | 20 |
| 精英 | 纯黑 + 中心 2 个白 pip | 3 | 30 |
| 钢砖 | 浅灰底(0xBB) + 黑描边 + 黑菱形点阵 | ∞ | 0 |
| **道具砖** | 纯黑 + 中心**白色菱形 pip**（宽度序列 2,4,6,8,6,4,2，对称菱形） | 1 | 30 |

> 决策：**四档灰度分层**——深灰(普通) / 纯黑(多血·道具) / 浅灰(钢砖)，血量仍由白色 pip 表达。
>
> 理由：①普通砖数量最多、最不值得瞄，让它退到深灰"背景层"，**值得打的砖自动跳出来**；②整墙不再是纯黑一坨，视觉有层次；③**不新增语义**——白 pip 仍是血量、菱形仍是道具，玩家不需要记第二套"灰阶→含义"的映射。
>
> 曾经考虑过"用灰阶编码血量"（普通黑 / 2 血深灰 / 3 血中灰），被否掉：白 pip 已经精确表达剩余血量，再叠一层灰阶是冗余，而且最值钱的精英砖会变成最暗的、还跟浅灰钢砖撞脸。
>
> **取色按砖的原始类型 `base`，不按当前血量**——受创过的砖不能变色，否则一次击打会整块换灰阶（墨水屏残影重）且与普通砖混淆。
>
> 道具砖的 pip 用**菱形**（而血量用方 pip），形状上就与"血量 pip"区分开——玩家一眼知道"这块砖会掉东西"，而不是"这块砖很硬"。

### 5.3 操控方案（触控）

| 手势 | 行为 |
|---|---|
| **拖动（pan）** | 挡板**实时跟随手指**。用 `ges.relative` 相对位移 + 锚点，**永不跳位**；阻尼系数 0.7，兼顾跟手与顺滑 |
| **点按砖阵区** | 球在挡板上待发时 → **发球**；飞行中 → 无操作 |
| **点按底部区** | 挡板**绝对跳转**到该 x（给不愿拖拽的用户的后备方案） |
| **双击** | 暂停 / 继续 |
| **顶栏按钮** | 暂停、重开、退出 |

> `pan` 限频 `rate = 25`（次/秒），避免 e-ink 上高频手势把主线程打满；锚点在 `pan_release` 时重置。

### 5.4 物理规则

- 球速：第 1 关 **150 px/s**，每关 +12 px/s，上限 265 px/s。600px 宽场地，竖直穿越约 4.5 秒——从容、可读。
- 挡板反弹：击球偏移 `off ∈ [-1,1]`（挡板半宽归一化）→ 出射角 `off × 57°`（`MAX_SPIN = 1.0 rad`），**出射角大小固定**、方向随击球点变化。
- 防死循环：横向分量强制 ≥ 12% 球速，杜绝垂直上下来回的死循环。
- 球速守恒（反弹不改速率），只有关卡推进才提速——保证"可预测"，这是玩家能玩的前提。

### 5.5 计分与关卡

- **连击 Combo**：同一球在两次触板之间连续击砖，每次 +0.1 倍率，上限 2.0×。
- **过关奖励**：`200 × 关卡 + 100 × 剩余生命`。
- **生命**：3 条，球掉出底线扣 1 条。
- **最高分**：持久化到 `DataStorage:getSettingsDir()/breakout_hiscore.txt`（与《方块战争》同模式）。
- **关卡**：
  1. 经典 5×10
  2. 6 行，混入 2 血砖
  3. 6 行，含两侧不可破钢砖墙
  4. 金字塔布局
  5+ **程序化生成**（随机阵列/棋盘/缺口 + 随机血量分布，球速递增）

### 5.6 掉落道具系统（v1.1 新增）

#### 5.6.1 道具从哪来

**不做"打碎任意砖有概率掉落"**，而是设置**专用道具砖**（白色菱形 pip，`*`）：

- 手工关卡每关**固定 6 块**道具砖（`*`，分散在不同行、避免堆在同一列）；程序化关卡的道具砖**随关卡递增：第 5 关 6 块 → 第 13 关起 10 块封顶**。撒点会重试到放满为止，不会因为随机位置不合法而少放。
- 好处：掉落**可预期、可学习**。玩家知道"哪几块砖会掉东西"，会去瞄准它们，而不是被动等概率。

#### 5.6.2 七种道具

| 道具 | 效果 | 时长 | 好坏 | 图标剪影 |
|---|---|---|---|---|
| **加长** | 挡板 96 → 132px | 12s | 增益 | 满宽横杠 |
| **多球** | 每颗球分裂出 ±20° 两颗，上限 4 球 | 即时 | 增益 | 三个点 |
| **减速** | 球速 ×0.7 | 12s | 增益 | 钟面 |
| **加命** | 生命 +1（上限 5） | 即时 | 增益 | 十字 |
| **吸盘** | 球吸附在挡板上，轻触释放 | 10s | 增益 | U 形碗 |
| **变短** | 挡板 96 → 64px | 10s | 减益 | 窄横杠 |
| **加速** | 球速 ×1.35 | 8s | 减益 | 双右箭头 » |

#### 5.6.3 墨水屏可读性设计：图标全靠形状，好坏靠底色

- 7 个图标全部是**纯几何剪影**（横杠 / 三点 / 钟面 / 十字 / U 碗 / 双箭头），**不依赖颜色**。
- **纯黑底 = 增益，浅灰底(0xBB) = 减益**。玩家一眼分好坏：黑底徽章去接，灰底徽章躲着走。
- 道具砖的白色**菱形** pip 与血量的**方形** pip 形状不同，不会混淆。

#### 5.6.4 掉落物理与残影对策

- 道具**竖直直落**（不抛物线），速度 **100 px/s**，每 tick 位移 10px——刻意压慢，保证残影是"一条淡影"而不是"一团糊"。
- 同屏掉落物上限 **3 个**；落点标记上限 **2 个**（超过就不画，防止标记过多）。
- 道具**落点用空心方框**，球的落点用**十字 + 黑心**——两种形状，玩家一眼分清"挡板该往哪挪"。
- 道具脏区只含徽章本身（28×28 + 2px 余量），运动物体多的场景也不会拉大刷新面。

#### 5.6.5 接取与生效

- 道具下落到挡板线（`PADDLE_Y`）时判定一次：横向距离 ≤ 挡板半宽即接住。
- 接住 → 立刻生效 → 底栏**效果条**显示图标 + 剩余秒数 + 一条 1.8s 的文字提示（toast）。
- **限时道具到期**自动失效：加长/变短恢复挡板宽度，减速/加速恢复球速。
- **加长优先于变短**（同时持有时挡板取长值），避免"刚加长又被变短"的挫败感。

#### 5.6.6 多球的特殊规则

- 上限 **4 颗**；分裂时每颗飞行中的球各分出 ±20° 两颗。
- **只有全部球都掉出底线才扣命**——墨水屏节奏慢，多球不该让玩家频繁丢命。
- 多球时**只预测最迫近的那一颗**（y 最大者）的落点，避免屏幕上一堆标记导致残影过重。

#### 5.6.7 吸盘

- 吸盘生效时，落到挡板上的球会**粘住**（速度归零、跟随挡板移动）。
- **轻触屏幕任意位置释放**（释放前不会自动弹回，避免误操作）。
- 同一时刻只吸附 1 颗球；吸盘期间底栏提示改为「轻触屏幕释放被吸附的球」。

## 六、技术架构

```
plugins/breakout.koplugin/
├── _meta.lua            # 插件元信息（名称/描述）
├── main.lua             # 菜单入口注册（与 tetris 同构：工具菜单置顶）
└── breakoutdialog.lua   # 游戏主体：物理 / 触控 / 渲染 / 关卡 / 计分
```

**与《方块战争》一致的架构约定：**

- 继承 `InputContainer`，`modal = true`，`dimen` = 全屏 `Screen:getWidth() × getHeight()`。
- 全部像素级绘制在 `paintTo(bb, x, y)` 里完成，**每帧整屏重绘**——KOReader 会自行 diff 出脏矩形并只推送变化部分，因此整屏重绘不带来额外刷新成本，却免去了手工维护图层。
- 定时器用 `UIManager:scheduleIn(TICK, ...)` 自续期；**必须自己保存 action 的函数引用**再 `UIManager:unschedule`（**否则插件退出后定时器仍在跑，会在后台空转刷屏**）——原因见下方"定时器层的坑"。
- 手势用 `registerTouchZones` + `ges_events` 双路注册。
- 最高分用 `io.open` 读写纯文本。

**KOReader 手势层的三个坑（真机实测，直接影响交互设计）**

1. **`disable_double_tap` 决定 tap 的送达时机**。`UIManager:show()` 里 `Input.disable_double_tap = widget.disable_double_tap ~= false`。
   - `false`（默认）：单次 tap 被**延迟 `ges_double_tap_interval`（300ms）** 才下发；且 300ms 内的两次 tap 会被合并成**一个 `double_tap` 事件，两个 tap 全部丢失**。
   - `true`：tap **立即下发**，不做双击合并。
   → 游戏要"点一下立刻响应"，必须设 `disable_double_tap = true`，双击自己在 tap 序列上判定。
2. **拖拽结束有两个出口**。手指抬起时：拖拽时长 < `ges_swipe_interval`（默认 **900ms**）→ 发 **swipe**；否则 → 发 **pan_release**。**只监听 `pan_release` 会漏掉所有快速拖拽**（而快速拖拽恰恰是游戏里最常见的操作）。
3. **`ges.relative` 是相对"本次按下的起点"的累计位移**，不是逐帧增量；而 `ges.start_pos` 就是该起点。所以"锚点 + relative"映射能天然消除起手跳位，但**锚点必须在每次拖拽结束时清零**，否则下一次拖拽会沿用上一次的映射而跳位。
4. **自定义 `onGesture` 必须转发给 `InputContainer.onGesture`**。`InputContainer:onGesture`（`frontend/ui/widget/container/inputcontainer.lua:259`）是**唯一**会遍历 `registerTouchZones` 注册的 `_ordered_touch_zones` 的入口（触摸区优先于 `ges_events`，命中即短路）。插件若自己重写 `onGesture` 却只做手工分支分发、不转发，**所有触摸区都是死代码**——"按区域分流"的手势会全部失灵，而且**不会有任何报错**。

**KOReader 定时器层的坑（真机实测）**

`UIManager:scheduleIn(seconds, action)` **没有返回值**（设备端 `frontend/ui/uimanager.lua:335`），而 `UIManager:unschedule(action)` 是按 `队列项.action == action` 匹配的 —— 所以**只有把 action 函数本身保存下来才能取消**。

```lua
-- ❌ 错误：self.timer_action 恒为 nil，unschedule 永远不执行
self.timer_action = UIManager:scheduleIn(TICK, function() ... end)

-- ✅ 正确：自己留住函数引用
local tick_timer
tick_timer = function() ... end
self.timer_action = tick_timer
UIManager:scheduleIn(TICK, tick_timer)
```

> 这个坑在《方块战争》里造成了一个会自我放大的 bug，详见 [`docs/TETRIS_ACCEL.md`](TETRIS_ACCEL.md) 的复盘一节。两个插件现已同步修正。

> 计时统一用 `Time.now()`（单调时钟 fts 定点值）。fts 是**线性**编码，`now - t` 与 `Time.s(0.06)` 同量纲可直接比较；不要拿 `ges.time`（事件时间戳，时钟源可能不同）或 `os.clock()`（设备上是 CPU 时间，几乎不走）来比。

**新增的工程抽象：脏区追踪**

```lua
-- 每 tick 累积"本帧哪里变了"，据此生成精确的刷新区域
self:markDirty(x1, y1, x2, y2)   -- 球旧位置/新位置、挡板旧/新、标记旧/新
```
→ `UIManager:setDirty(self, "ui", Geom:new{...})` 只推这块区域；砖阵区另行低频维护。

**刷新层的四条铁律（v1.3，真机实测得出）**

墨水屏上"多刷一次"的代价远比想象大：局部刷新不是免费的，它会留残影、耗电，还会让 KOReader 把它升级成全屏黑闪。这一版的刷新层踩过四个坑，全部有真机证据：

1. **静止时必须一个像素都不刷新。**
   曾经每 tick 无条件把"挡板区"标脏推送，静止画面也在 **10Hz** 刷面板。
   真机连拍 10 帧，**2 帧糊掉半屏**（底栏整条空白、砖阵下半截丢失）——
   截图抓到的是面板**正在刷新中的瞬态**，而用户看到的就是实打实的闪烁。
   → 现在只有"真的动了"才标脏：球位置变了、挡板位置/宽度变了、标记增删了，才进脏区。
   → 修完的验收标准：**静止画面 10 连拍逐像素完全一致**（`tools/measure_botbar.py`）。

2. **脏区必须"用完即清"。**
   运动脏区桶曾经只 push 不清空，矩形会随着球跑过的地方**越滚越大**，
   最后变成"每次都刷新整屏"——墨水屏直接跪。
   → `doRefresh()` 推完就把 `_dr.field` 置 nil。

3. **底栏要按格刷新，不能整条刷。**
   整条底栏是 580×92；分数一变就整条重刷 = 每打碎一块砖底栏整块闪一下。
   现在按字段分格（分数/最高/生命/关卡/速度 各一格 + 效果条），只推变化的那一格（约 108×20）。
   → 相邻格之间**刻意留 4px 间隙**：KOReader 会把"共享边界"的矩形合并成一次刷新，贴着排就会被并成一大块。
   → 状态切换**不再**整条标脏——底栏内容已由逐字段比对完全覆盖。

4. **碎砖当场擦，别等低频维护刷新。**
   以前 `damageBrick` 只置一个 `brick_force` 标志，等 0.5s 一次的"砖阵区维护刷新"（555×167 整片）才去擦，
   碎砖残影要挂半秒，而且那一刷贵得离谱。
   → 现在击碎当场把**那一格**标脏（独立砖阵桶，与运动区分开推），维护刷新降到 6s 一次且只在游戏中做。

**KOReader 刷新队列的真实规则（设备端 `frontend/ui/uimanager.lua` 读出来的）**

- `UIManager:_refresh(mode, region)`：入队时用 `Geom:openIntersectWith` 判定冲突，
  **共享边界的两个矩形也会被合并**（源码注释原话：*"we use the open range variant, as we want to combine rectangles that share an edge (like the EPDC)"*）。
- 队列出队时是**逐条执行**的（`refresh_methods[mode](Screen, x, y, w, h, dither)`），
  所以**互不相交的矩形各刷各的**——分桶的意义就在这里。
- `"ui"` 模式**不会**被升级成全屏黑闪（只有 `"partial"` 会，每 `FULL_REFRESH_COUNT` 次升级一次）。

> ⚠ 分桶的桶名必须**原样使用**。底栏各格的矩形在 731 行往下，如果被并进"运动脏区"桶，
> 会被运动脏区那道"下边界夹到 707"的钳制直接丢弃（高度算成负数），底栏就永远刷不出来。
> 这个坑踩过一次：`markRect` 里没认 `"barscore"` 这类新桶名，全部落进了运动区桶。

**开发过程中发现并修复的三个真机硬伤**（均为只看代码发现不了、必须上机才暴露）

1. **双击暂停完全失效**。KOReader 在 `disable_double_tap = false` 时，会把单次 tap **延迟 300ms** 才下发，并把 300ms 内的两次 tap **合并成一个 `double_tap` 事件、两个 tap 全部丢弃**。原先"在 tap 序列上自己判双击"的实现前提根本不成立。**修法**：对话框设 `disable_double_tap = true`（tap 立即送达），双击改为在 tap 序列上自行判定；计时用 `Time.now()`（单调时钟 fts），与 `Time.s(0.06)` 同量纲可直比。
2. **拖拽第二次开始挡板跳位**。手势检测器中，拖拽时长 < 900ms（`ges_swipe_interval`）会被判成 **swipe** 而不是 `pan_release`，于是 `pan_release` 处理器收不到事件、拖动锚点跨次残留，第二次拖拽时挡板会跳到上一次锚点对应的错误位置（实测出现"向左拖、挡板反而向右跑"）。**修法**：同时注册 `swipe` 与 `pan_release` 两条通路清除锚点。
3. **底栏与状态浮层永远不会上屏**。增量刷新只把"运动脏区"（球/挡板/落点标记/道具）推给面板，而**底栏（分数/生命/效果条）与"游戏结束"浮层所在的区域从不被标脏**——于是分数在面板上长期停留在 0、提示文字被截断，"游戏结束"浮层要等到下一次全屏刷新才闪现出来。**修法**：把脏区从"单一包围盒"拆成**独立桶**（运动区 / 底栏各格 / 浮层 / 砖阵区），底栏用**逐字段指纹**判断是否变化（只在真的变了才推那一格），状态切换时显式标脏浮层矩形。

**v1.3 又挖出并修掉的第四个硬伤：静止时也在刷屏**

症状是"底栏偶尔整条空白、砖阵下半截消失"（真机 10 连拍有 2 帧如此）。
一开始怀疑是 KOReader 把"共享边界"的矩形合并了（后来证实**确实**会合并，源码 `Geom:openIntersectWith`），
但真正的根因是**插件自己**：每 tick 无条件把挡板区标脏推送，静止画面也在 **10Hz** 刷面板；
而运动脏区桶**推完不清空**，矩形随着球跑过的地方越滚越大，最后变成整屏刷新。
截图抓到的"半屏糊掉"正是面板**正在刷新中的瞬态**——用户看到的就是实打实的闪烁。
**修法**：只有真动了才标脏 + 脏区用完即清 + 底栏按格刷 + 碎砖当场擦。
**判据也换了**：以前靠肉眼看截图，现在用 `tools/measure_botbar.py` 做**连拍逐像素比对**，
静止画面必须 10/10 帧完全一致才算过。

**一键脚本**
- `./tools/deploy_breakout.sh [KINDLE_IP]` —— 部署 + 清理设备临时文件 + 打开游戏并截图。
  插件采用 `package.loaded["breakoutdialog"] = nil` 的软部署方式，**覆盖文件即可生效，无需重启 KOReader**（重启 KOReader 曾导致 SSH "Connection reset by peer"）。

## 九、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 局部刷新跟不上 10Hz | 球看起来"一卡一卡" | 降 TICK 至 120ms；脏区只含运动物体，刷新面积极小 |
| 砖阵区维护刷新导致卡顿 | 操作延迟 | 已降为 6s 一次且只在游戏中做；碎砖改为当场精确擦那一格，维护刷新只负责清理 e-ink 残影 |
| 预测计算吃 CPU | 掉帧 | 预测步长 6px、上限 1200 步、只在砖阵高度带内做砖块检测；实测 <5% CPU |
| 手势与 KOReader 阅读器手势冲突 | 误触发 | 模态全屏 `InputContainer` 独占手势；`pan` 限频 25/s |
| 球速过快时手忙脚乱 | 不好玩 | 速度上限 265 px/s；击球点角度可预测；落点标记兜底 |
| 关闭插件后定时器泄漏 | 后台空转耗电 | `onClose` 中 `unschedule` + `is_closed` 双重守卫（与《方块战争》一致） |
