# 数独 (Sudoku) - 墨水屏设计方案与真机验证

> 插件路径：[`plugins/sudoku.koplugin/`](../plugins/sudoku.koplugin/)
> 无头测试台：[`tools/sim_sudoku.lua`](../tools/sim_sudoku.lua)
> 目标设备：Amazon Kindle **Basic 第 7 代（KT2 / 设备码 C6）**，600×800、16 级灰度、**无前光**

---

## 1. 为什么数独特别适合墨水屏

打砖块、俄罗斯方块这类游戏的难点在于**连续动画**与墨水屏 5–15fps 的刷新率天然打架。
数独反过来：它本来就是**静态纸面游戏**，一局里没有任何需要动的东西。

因此本插件的刷新预算是整个仓库里最省的：

| 场景 | 刷新行为 |
| :--- | :--- |
| 静止不操作 | **一个像素都不刷**（只有计时器每秒刷一次状态条的时间格） |
| 选一格 | 只刷该格（52×52）+ 数字键盘（9 个小按钮） |
| 填一个数 | 只刷该格 + 数字键盘 |
| 切难度 / 新局 | 全屏刷一次（换局本身就是新画面） |
| 完成浮层 | 单独一个刷新桶 |

刷新分层沿用《砖石战场》v1.3 沉淀的铁律：**脏区用完即清、分桶且桶名原样使用、相邻刷新块留 1px 以上间隙**。

## 2. 视觉设计：只用形状，不用颜色

墨水屏 16 级灰度 + 无前光，任何依赖"红/绿/黄"区分的信息全部失效。本插件的每一条信息都用**形状**编码：

| 信息 | 编码方式 |
| :--- | :--- |
| 题目给定的数字 | 纯黑粗体，**数字下方无横线** |
| 玩家填入的数字 | 纯黑粗体 + **数字下方一条 2px 短横线** |
| 笔记得号 | 3×3 排布的小号浅灰字（退到背景层） |
| 数字冲突（同行/列/宫重复） | **横穿数字的删除线**（不是红字） |
| 当前选中格 | 内嵌 3px 粗框（**不做整行整列反白**） |
| 键盘上"本行/列/宫已用"的数字 | 按钮变浅灰 + 数字变浅灰 |

> 为什么不用"整行整列反白"：反白要刷 3 条 9 格长的条带（9×52×3 ≈ 1400px），
> 而把 9 个数字按钮变灰只要 9×57×80 的零头，**省一个数量级的刷新预算**，
> 而且信息量完全等价（"哪些数字还能填"）。

## 3. 出题算法

标准做法是"每挖一个洞就验一次唯一解"，复杂但慢。本插件用的是**两阶段**：

1. **无脑挖空**：从完整解出发，按随机顺序逐格置空，直到空格数达到目标
   （简单 42 / 普通 32 / 困难 25 个给定），此阶段**不做任何求解**，纯随机。
2. **逆序恢复直到唯一解**：把第 1 步挖掉的格子**按逆序**逐个试填回去，
   每填一个就用 `countSolutions(grid, limit=2)` 数一解；
   若填入后仍然唯一解，就保留这个数字（它是被"逼出来"的），
   否则把它清掉（这个洞是必需的）。
   逆序处理的好处是**后面的洞更可能是多余的**，能更早触发"不再唯一"的判定。

求解器用 **MRV（Minimum Remaining Value）回溯**：
每次从当前棋盘里"候选数最少"的格子展开分支，候选数为 0 直接剪枝。
计数到 2 就提前返回（只需知道"是不是唯一"）。

**实测性能**（Mac 上，`tools/sim_sudoku.lua`）：困难局平均 **0.013 秒/局**，
真机上也在 100ms 量级 —— 点「新局」不会有可感知的等待。

> 真机验证时留意：`generateSolution()` 用了 `math.random()` 且**没有固定种子**，
> 真机每次开局都不同，这正是期望行为；无头测试台里用固定种子保证可复现。

## 4. 交互设计（纯触控盲操）

```
顶栏    [数独]                    [难度] [新局] [退出]
────────────────────────────────────────────────────────
棋盘    9×9，格子 52px，整体 468×468，横向居中
────────────────────────────────────────────────────────
状态条  难度:普通        用时:03:46        空格:36
────────────────────────────────────────────────────────
数字键盘  [1][2][3][4][5][6][7][8][9]
────────────────────────────────────────────────────────
操作行  [擦除]  [笔记]  [撤销]  [提示]
────────────────────────────────────────────────────────
提示行  点数字填入 · 长按格子清空 · 灰掉的数字本行/列/宫已用
```

- **点格选中 → 点数字填入**；再点同一个数字 = 擦除该格。
- **长按格子** = 清空该格（KOReader 的 `onHold`）。
- **笔记模式**：切到笔记后点数字 = 增删该格的候选数（9 位掩码，用 `2^(d-1)` 算术位运算，
  不引入 `bit` 库，保证 LuaJIT 5.1 与本地 5.3/5.4 双端可跑）。
- **撤销**：栈式撤销，覆盖填数/擦除/笔记/提示。
- **提示**：填一个正确的数进空格，并累计提示次数（提示行右侧显示）。
- **完成判定**：81 格填满且与解一致 → 弹完成浮层（用时 + 各难度最佳用时）。

### 存档

- `DataStorage:getSettingsDir()/sudoku_save.txt` —— 8 行文本：given / val / notes / solution / hints / elapsed / 难度 / 版本。
  退出插件不丢局，重开自动续上（真机验证时可以看到"用时"接着上次累计）。
- `DataStorage:getSettingsDir()/sudoku_stats.txt` —— 完成局数 + 各难度最佳用时。

### ⚠️ 这台机的触控注入坑

KT2 的 zforce2 触摸驱动**不接受外部 evdev 注入**：往 `/dev/input/event1` 写 `input_event`
时 `write()` 成功返回 16 字节，但**事件进不了输入子系统**（另开读端抓不到任何事件），
所以"写 evdev 式"的点击脚本在真机上**完全无效**，看起来像插件不响应点击。

可行做法是把合成事件直接喂给 KOReader 的 `Input:handleTouchEv`，
由真正的 `GestureDetector` 识别成 tap / hold，再经 `UIManager:sendEvent` 派发给顶层控件 ——
与真实手指完全同一条链路。该助手已随 skill `kindle-screen-automation` 一起提供
（`scripts/kr_tap_helper.koplugin` + `scripts/tap.sh`）。

### 墨水屏截图的通用坑

面板正在局部刷新时截图会抓到**"撕裂帧"**（半新半旧），看着像渲染 bug。
判据：同一元素在相邻多帧像素完全一致、只有孤零零一帧异常 → 是撕裂帧。
**别凭单张截图下渲染 bug 的结论**，至少连拍 3 帧。

## 6. 无头测试台

```bash
lua tools/sim_sudoku.lua
```

mock 掉 KOReader 依赖（Font / RenderText / UIManager / Blitbuffer），
28 项断言覆盖：出题唯一解、题面合法、给定数达标、填数/擦除、给定格不可改、笔记、
撤销、冲突判定、完成判定、存档往返、提示、**脏区只刷那一格**、**无操作零刷新**。

> 用例之间必须隔离棋盘（每个用例先删存档再 new），
> 否则"填满判完成"会把完整盘存盘、污染后续用例。
